# Deploy Support Desk on AWS

This checklist applies to one EC2 instance running the included Compose service. Plan the AWS account, region, hosting budget, and authorized operators before provisioning.

1. **Compute and network.** Use a supported Linux EC2 image and install Docker with the Compose plugin. Keep the container listener bound to loopback. Use Systems Manager Session Manager for administration where available. For external users, terminate HTTPS at an approved proxy and expose only the required HTTPS ingress. Keep Ollama restricted to the backend network. [EC2 security groups](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-security-groups.html) · [Session Manager](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager.html)
2. **Data and secrets.** Put application SQLite files on persistent encrypted EBS storage. Bind the backup or order data directory into the container read-only as appropriate. Take SQLite-consistent backups and verify restores. Use a private encrypted S3 bucket for backup copies. Supply `JWT_SECRET_KEY` through the deployment environment or a managed secret, and keep `DEMO_REFUNDS_ENABLED=false` for hosted deployments. [Amazon EBS encryption](https://docs.aws.amazon.com/ebs/latest/userguide/ebs-encryption.html) · [Amazon S3 encryption](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingEncryption.html)
3. **IAM.** Attach an instance role limited to the needed backup, monitoring, and management actions. Keep AWS access keys out of the project and container image. [IAM roles for EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/iam-roles-for-amazon-ec2.html)
4. **Ollama.** The app expects an Ollama-compatible base URL. Provision the installed `qwen3:1.7b` model on the EC2 host or a separate private inference host. Set the URL in a Compose override if the inference service runs elsewhere. Measure memory and latency with the expected number of users before choosing instance size. A hosted provider with a different API would require an adapter.
5. **Application.** From the verified checkout, supply `.env` and a read-only order database, then run `docker compose up --build -d`. For a demonstration, use synthetic data. Provision an admin with `docker compose exec support python -m backend.provision_staff_user`.
6. **Monitoring.** Use the CloudWatch agent or approved logging integration to collect server logs. Restrict access and retention. The app logs workflow, status, and latency information. Admins can inspect assistant counters at `/admin/metrics`, and `SUPPORT_OTEL_CONSOLE=true` enables local OpenTelemetry spans. [CloudWatch agent installation](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/install-CloudWatch-Agent-on-EC2-Instance.html)
7. **Acceptance checks.** Verify `/health` and `/ready`, sign in with a test account, run a cited policy query, confirm a synthetic return, and check that staff approval and role restrictions work. Test restoring an application database copy and reading the logs. Keep the app on a single instance while it uses local SQLite and process-local rate limits.

A deployment is ready for release when these checks pass on the intended AWS environment.
